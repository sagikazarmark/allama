# Every key path of a serialized `ChatRequest`, and how the request field
# audit (C2, `allama_conformance::probe::assert_request_fields_accounted`)
# accounts for it.
#
# Each line is a key path and an account:
#
#   <path>  probe: <probe>[, <probe>...]   C2 probes check it.
#   <path>  exempt: <reason>               C2 does not probe it, for <reason>.
#
# Paths follow the serialized form. Arrays add `[]`; an object tagged with
# `role` or `type` adds its tag as a segment, so `messages[].user.cache{}` is
# `UserMessage::cache`. A path ending in `[]` or `{}` accounts for the whole
# array or object there (`provider_data{}` is the provider data map); any
# other path accounts for a single value.
# Probe names are the snake_case names of `allama_conformance::probe::Probe`.
#
# A test in this package serializes a request with every field and every
# message, part, and block kind set, and fails on any path that is not
# listed here or is listed but no longer serialized. A new field therefore
# lands with a probe or an explicit exemption.
